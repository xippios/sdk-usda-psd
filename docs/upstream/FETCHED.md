# Upstream documentation snapshot — USDA FAS PSD Online

Source of truth for every endpoint wrapper (ADR-0003). The files in this directory are
written by `scripts/refresh_upstream.py` (`/refresh-upstream`) from the documents in the
table below and refreshed deliberately by PR, so that changes show up as diffs. This
file is generated by the same script. Nothing here was edited by hand.

## Attribution

The documentation is a work of the United States Government (USDA, Foreign Agricultural
Service), in the public domain in the United States under 17 U.S.C. § 105. No page or
document this script reads states a copyright line, a licence or terms of use: neither
Swagger document's `info` names a licence, terms of service or contact, neither
document's text states one, and the markup of the portal page, the classic Swagger UI
page and the PSD Online page states none. The visible text of the portal and of PSD
Online, their footers included, is drawn by scripts that this script does not read (the
portal's bundle embeds a key), so what the rendered pages state is not read here. FAS's
data page, https://www.fas.usda.gov/data, answers 403 Access Denied at the CDN edge to
this script, so what it states is not read here either. The script stops if a page or
document it reads starts to state one that it does not record. The documentation's text
is reproduced here as this package's reference (ADR-0003); an objection from the
publisher is met by replacing it with a summary that keeps the names and semantics the
wrappers rely on.

## How this is captured

The FAS Open Data Services portal, https://apps.fas.usda.gov/opendatawebV2/, documents
three APIs of USDA's Foreign Agricultural Service: ESR, GATS and PSD. It is an Angular
app whose page is a shell without documentation text. Its Swagger window loads the
Swagger 2.0 document
https://apps.fas.usda.gov/opendatawebV2/assets/swagger/swagger.json. On 2026-10-23 the
session that set up this snapshot fetched the portal page and its JavaScript bundle into
a session-local scratch directory and found that URL in the bundle's Swagger UI
configuration; those copies have since been deleted. The script never downloads the
bundle, since it embeds the portal's own api.data.gov signup-widget key, and this file
records only its file name: as of this run the portal page loads
`main.6da18f8b4fa8a2baed40.js`.

The API also serves its own Swashbuckle document,
https://apps.fas.usda.gov/OpenData/swagger/docs/v1, which the classic Swagger UI at
https://apps.fas.usda.gov/opendata/swagger/ui/index loads; the script reads that URL
from the UI page's `rootUrl` and `discoveryPaths`. Both documents are kept because they
are two upstream statements of the same API that need not agree on how it is reached. As
fetched, their PSD parts differ in `host` and `securityDefinitions`; only the portal
document has `security`; only the backend document has `basePath`; they agree in
`swagger`, `info`, `schemes`, `paths` and `definitions`.

Both documents cover ESR, GATS and PSD, and ESR and GATS get their own packages in this
family, so each file here holds the PSD part only: every top-level field verbatim and in
upstream order, `paths` reduced to the keys starting with `/api/psd/` and `definitions`
reduced to those the kept paths reference, directly or through other definitions; each
document's row counts the paths kept and dropped, per prefix. The script writes the part
with `json.dumps(indent=2, ensure_ascii=False)` in upstream key order, with LF line
endings and a final newline, and stops unless the full document re-serialised the same
way reproduces the fetched text up to line endings, so each file is the upstream text
with the other APIs cut out. Bytes and sha256 in a document's row are those of the full
document as fetched, so a change anywhere in it shows here.

Pages that are client-rendered shells or that refuse headless clients get no file, only
a row with their HTTP status and the size and sha256 of the body. The 403 body carries a
per-request reference number and so changes on every request; its row records no size,
sha256 or validators.

Fetched is the UTC time the run started, in ISO 8601 with an explicit Z, the same for
every row. Two runs against the same upstream write byte-identical files under
`openapi/`, and this file differs between them in its Fetched column only. Last-Modified
is the HTTP header in UTC, ETag as sent, `-` where none is sent. Requests go one at a
time, 2 s apart, each retried at most once, identified as `xippios-usda-psd
refresh_upstream (+https://github.com/xippios)`; no API key is sent or read.
